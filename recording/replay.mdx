---
title: "MCAP Replay"
description: "Replay a recorded session through the same API as a live device"
---

A recorded `.mcap` replays through the **same** `Device` API — point
`InitParameters` at the file instead of a transport and the grab loop is
unchanged. Code written against a live device runs against a recording
verbatim, the same way an SVO file works in the ZED SDK.

```cpp
InitParameters init;
init.input_type = INPUT_TYPE::MCAP;
init.mcap_path  = "session.mcap";

Device dev;
if (dev.open(init) != ERROR_CODE::SUCCESS) return 1;

Mat image;
SensorsData sensors;
for (;;) {
    ERROR_CODE ec = dev.grab();
    if (ec == ERROR_CODE::END_OF_BUFFER) break;   // file exhausted
    if (ec != ERROR_CODE::SUCCESS)       continue;
    dev.retrieve_image(image);
    dev.retrieve_imu(sensors);
}
dev.close();
```

The differences from a live session:

- `grab()` returns `END_OF_BUFFER` when the file runs out — the one loop-exit
  condition unique to replay.
- Control-plane calls (health, WiFi, recording management) return
  `INVALID_FUNCTION_CALL` — there is no device.
- Timestamps are the original capture timestamps from the recording.

Both host-file and device-local recordings replay identically — they share
one schema. Recordings also open directly in Foxglove. To convert a session
to a standard video file, use the bundled script:

```sh
python3 sdk/linux/tools/mcap_to_video.py session.mcap session.mp4
```

<Note>
If HEVC won't play in Foxglove on Linux, record `h264` instead, or transcode
with `mcap_to_video.py`.
</Note>
