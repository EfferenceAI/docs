---
title: "OpenCV"
description: "Zero-copy interop between ef::Mat and cv::Mat"
---

The SDK ships an optional, header-only OpenCV bridge — the Efference analogue
of Stereolabs' `slMat2cvMat()`. The core library does **not** depend on
OpenCV; include `<ef/opencv.hpp>` only in code that already links OpenCV.

```cpp
#include <ef/Device.hpp>
#include <ef/opencv.hpp>
#include <opencv2/highgui.hpp>

ef::Mat frame;
dev.retrieve_image(frame, ef::VIEW::BGR);
cv::imshow("efference", ef::toCvMat(frame));   // zero-copy view
```

Ask `retrieve_image()` for `VIEW::BGR` (or `VIEW::BGRA`) and the returned
`cv::Mat` is display-ready with no color conversion — the SDK already
converts on the decode path, and BGR is OpenCV's native channel order.

## Lifetime rules

`toCvMat()` returns a **view**: both `Mat`s share the same pixel buffer, so
the call is O(1) with no allocation. The `cv::Mat` is valid only while the
`ef::Mat` stays alive and unmodified — the next `retrieve_image()` into the
same `ef::Mat` overwrites the pixels. Call `.clone()` if you need to own them
longer.

## View mapping

| `VIEW` | `cv::Mat` | Notes |
|---|---|---|
| `BGR` | `CV_8UC3` | ready for `cv::imshow` |
| `BGRA` | `CV_8UC4` | ready for `cv::imshow` |
| `NV12` | `CV_8UC1`, `height * 3/2` rows | convert with `cv::cvtColor(nv12, bgr, cv::COLOR_YUV2BGR_NV12)` |

An uninitialised `ef::Mat` yields an empty `cv::Mat`.

## Runnable example

`examples/opencv/01_opencv_display.cpp` builds automatically when OpenCV is
present (`apt install libopencv-dev`) and is skipped otherwise:

```sh
./build/opencv_01_opencv_display              # USB
./build/opencv_01_opencv_display --ble <MAC>  # Bluetooth control
```

Press `Esc` or `q` to quit. Once a frame is a `cv::Mat` it drops straight
into any OpenCV pipeline.
