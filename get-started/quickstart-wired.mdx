title: "Quickstart — Wired (USB)"
description: "Plug in the M1, read its identity, run a health check, and see live video"
---

Everything in this guide uses the USB cable only — no WiFi or Bluetooth setup.

<Steps>
  <Step title="Plug in and discover">
    ```sh
    ./sdk/linux/build/ef-cli list
    ```
    Every attached M1 prints with its `device_id` and serial. If nothing shows
    up, check the cable (data, not charge-only) and the udev rule
    (see [Install Linux](/get-started/installation) or
    [Install Jetson](/get-started/install-jetson)).
  </Step>
  <Step title="Device information">
    ```sh
    ./sdk/linux/build/ef-cli info
    ```
    Serial, firmware version, enabled capture modes, camera calibration, IMU
    noise densities, and WiFi/BT MAC addresses — everything cached by the SDK
    at `open()`.
  </Step>
  <Step title="Health check">
    ```sh
    ./sdk/linux/build/ef-cli health          # quick sweep
    ./sdk/linux/build/ef-cli health --deep   # + ~2 min stress tier
    ```
    Each probe prints `PASS` / `FAIL` with detail.
  </Step>
  <Step title="Live video">
    ```sh
    ./sdk/linux/build/efference-viewer
    ```
    A window opens with the decoded stream and a status bar with live IMU
    values. `Q` or `Esc` quits.
  </Step>
</Steps>

## The same thing in C++

```cpp
#include <cstdio>
#include <ef/Device.hpp>

using namespace ef;

int main() {
    Device dev;
    ERROR_CODE ec = dev.open();   // USB is the default transport
    if (ec != ERROR_CODE::SUCCESS) {
        std::printf("open failed: %s\n", to_string(ec));
        return 1;
    }

    DeviceInformation info = dev.get_device_information();
    std::printf("serial:   %s\n", info.serial.c_str());
    std::printf("firmware: %u\n", info.firmware_version);

    HealthStatus health;
    if (dev.health_check(health) == ERROR_CODE::SUCCESS)
        std::printf("health:   %s\n", health.passed ? "PASS" : "FAIL");

    dev.close();
    return 0;
}
```

<Note>
`open()` claims and configures the device. The first `grab()` starts the live
USB data plane and waits for a frame; there is no separate start-streaming
call.
</Note>
