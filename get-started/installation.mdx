Use the automated installer on Ubuntu or another apt-based Linux host.

## Before you begin

- Ubuntu 22.04 or 24.04 is recommended
- Connect the M1 with a USB-C data cable, preferably to a direct USB 3.x port
- Your user must be able to run `sudo` for the first-time `--deps` install,
  which adds apt packages and the USB udev rule

See [Recommended Specifications](/get-started/requirements) for compatible
hosts and device requirements.

## Install

<Steps>
  <Step title="Clone the public repository">
    ```sh
    git clone https://github.com/EfferenceAI/efference.git
    cd efference
    ```
  </Step>
  <Step title="Build the Linux SDK">
    ```sh
    ./build.sh --deps
    ```

    `--deps` installs packages and the M1 USB udev rule, then builds the SDK
    and tools. This first run uses `sudo`.
  </Step>
  <Step title="Re-plug the M1">
    The installer creates `/etc/udev/rules.d/51-efference.rules`. Disconnect
    and reconnect the device after the first installation so the new
    permissions take effect.
  </Step>
  <Step title="Verify the installation">
    ```sh
    ./sdk/linux/build/ef-cli list
    ./sdk/linux/build/ef-cli info
    ```

    `ef-cli list` should discover the connected M1. `ef-cli info` prints its
    serial, firmware version, capture modes, camera configuration, IMU
    parameters, and wireless status.
  </Step>
</Steps>

The binaries are written to `sdk/linux/build/`:

| Tool | Purpose |
|---|---|
| `ef-cli` | Device discovery, configuration, health, recording, WiFi, and updates |
| `efference-viewer` | Decoded live video with IMU status |

<Note>
After installation, run `./build.sh` to rebuild without changing packages or
USB permissions.
</Note>

## Put `ef-cli` on your PATH

The examples throughout these docs use the full path
`./sdk/linux/build/ef-cli`, which always works and needs no setup. Two ways to
shorten it:

```sh
source ./env.sh                 # this shell only
./build.sh --install            # install to /usr/local (sudo, once)
```

`source ./env.sh` also sets `CMAKE_PREFIX_PATH` so the bundled tutorials
resolve `find_package(ef)`. It affects the current shell only; add the line to
your `~/.bashrc` to make it stick, or use `--install` to skip sourcing
entirely.

## Other build options

```sh
./build.sh                      # rebuild; never touches /etc
./build.sh clean                # wipe the build directory first
./build.sh --udev               # install just the USB rule (sudo), then exit
./build.sh --tutorials          # also build every bundled tutorial
```

`--udev` is the one to reach for if you built without `--deps` and hit
`INSUFFICIENT_PERMISSIONS`.

## Linking against the SDK

Link against the `ef::ef` target. With the SDK built in place, point CMake at
the build tree — `source ./env.sh` does this for you — and use
`find_package()`:

```cmake
find_package(ef REQUIRED)
target_link_libraries(my_app PRIVATE ef::ef)
```

Or add the SDK to your own tree as a subdirectory:

```cmake
add_subdirectory(efference/sdk/linux)
target_link_libraries(my_app PRIVATE ef::ef)
```

```cpp
#include <ef/Device.hpp>
```

The bundled tutorials under `tutorials/` are the working template — one
runnable project per topic, each building standalone against the SDK. Build
them all with `./build.sh --tutorials`, or run the `build.sh` inside any single
tutorial directory.
