title: "Device"

`ef::Device` is the single entry point to the SDK. It is move-only (one handle
owns one device session).

Key behavior:

- `open()` claims and configures a live device, caches its identity, and
  normally leaves it ready in `IDLE` (existing device activity may report
  `STREAMING`). The first `grab()` starts the USB or WiFi/UDP data plane.
  MCAP replay creates its reader during `open()`.
- Calls that touch the wire return `ERROR_CODE`; data comes back through
  `out` parameters. `get_*` methods without an `ERROR_CODE` never block —
  they return cached values.
- Illegal calls for the current `DEVICE_STATE` return
  `INVALID_FUNCTION_CALL` without touching the device.

## Lifecycle

```cpp
static std::vector<DeviceProperties> get_device_list(bool scan_ble = false,
                                                     uint32_t scan_ms = 3000);
```
Discover attached devices — USB always, BLE advertisers when `scan_ble` is
set. Static: needs no open handle.

```cpp
ERROR_CODE open(InitParameters params = InitParameters());
bool       is_open() const;
bool       is_authenticated() const;
void       close();
InitParameters get_init_parameters() const;
DEVICE_STATE   get_state() const;
```
`open()` validates the session configuration against the device's enabled
capability menu (`INVALID_RESOLUTION` / `INVALID_FPS` /
`UNSUPPORTED_COMPRESSION`), syncs the device clock, and prepares capture.
`close()` stops any host-file recording and releases the transport. It does
not stop a device-local recording. `get_state()`
returns the last known `DEVICE_STATE` and never blocks.

`is_authenticated()` reports whether this session proved the control password. It
is meaningful only when the device gates the link, which means any BLE link or a
USB one where `DeviceInformation::usb_locked` is set. `open()` deliberately
**succeeds with a wrong password**, because a gated device still answers `info`,
`state` and `storage`, and those are what an operator needs while recovering a
device whose password they have lost. Check this before calling a gated verb. See
[Access Control and Encryption](/device/security).

```cpp
bool poll_fault(std::string* reason = nullptr);
```
Refresh the device state from the firmware state machine (so a following
`get_state()` is fresh too) and report whether a fault is latched. A latched
device has entered SAFE and needs a health-gated recovery; because the
`DEVICE_STATE` enum has no fault value it projects `CLOSED`, so `poll_fault` is
how you tell a fault-closed device from a not-open one. When `reason` is set it
receives the most recent anomaly cause, populated both for a latched fault and
for an abnormal session end (for example `disk_full`, `capture_stopped`), and
empty once a clean session starts, so check `reason` even when the return is
`false`.

## Data plane

```cpp
ERROR_CODE grab(RuntimeParameters params = RuntimeParameters());
RuntimeParameters get_runtime_parameters() const;
```
Block until the next frame is assembled (at most `grab_timeout_ms`).
Returns `SUCCESS`, `GRAB_TIMEOUT` (non-fatal, loop), `CORRUPTED_FRAME`
(lossy frame; delivered only with `return_partial`), `END_OF_BUFFER`
(MCAP replay exhausted), or `COMMUNICATION_ERROR` (transport died).

```cpp
ERROR_CODE retrieve_image(Mat& mat, VIEW view = VIEW::NV12);
```
Decode/convert the grabbed frame into `mat` in the requested `VIEW`. The `Mat`
owns its buffer. Without the FFmpeg build the only supported combination is a
`COMPRESSION_MODE::RAW` session retrieved as `VIEW::NV12`; anything else
returns `UNSUPPORTED_COMPRESSION`.

```cpp
ERROR_CODE retrieve_imu(SensorsData& data,
                        TIME_REFERENCE ref = TIME_REFERENCE::IMAGE);
```
Drain queued IMU samples in chronological order.

```cpp
Timestamp get_timestamp(TIME_REFERENCE ref = TIME_REFERENCE::CURRENT) const;
```
`IMAGE` = last grabbed frame's capture time (device clock); `CURRENT` = host
wall clock now.

## Recording

```cpp
ERROR_CODE enable_recording(RecordingParameters params);
ERROR_CODE disable_recording();
RecordingParameters get_recording_parameters() const;

ERROR_CODE get_recording_status(RecordingStatus& out, const std::string& name = "");
ERROR_CODE list_recordings(std::vector<RecordingStatus>& out);
ERROR_CODE get_storage(uint64_t& free_bytes, uint64_t& total_bytes);
ERROR_CODE delete_recording(const std::string& name);
ERROR_CODE download_recording(const std::string& name, const std::string& dest_path);
ERROR_CODE upload_recording(const std::string& name, const std::string& url);
ERROR_CODE stop_upload(const std::string& name);
```
`HOST_FILE` writes the live stream to a local MCAP file. `DEVICE_LOCAL`
records on the M1 and survives `close()` or disconnect. Downloads use the
USB or Bluetooth LE (BLE) control link; uploads use WiFi.

## Updates

```cpp
ERROR_CODE check_update(UpdateAvailability& out);
ERROR_CODE update(const std::string& url = "",
                  const std::function<void(const UpdateStatus&)>& on_progress = {});
ERROR_CODE abort_update();
ERROR_CODE get_update_status(UpdateStatus& out);
const std::string& last_error_message() const;
```
`check_update()` is one host-side request to the update-check service and
downloads nothing. An empty `url` means "install what the service offers"; an
`https://` URL is downloaded as given; a **local `.eff` path** is pushed over the
wire, which needs USB. `update()` blocks through apply and reboot, reporting
progress via the callback.

`last_error_message()` returns whatever refused, the device or the service, in its
own words. The `ERROR_CODE` is a category, and this is usually the actionable part.

## WiFi, time, location, admin

```cpp
ERROR_CODE wifi_add(const std::string& ssid, const std::string& psk,
                    const std::string& country = "");   // "US" unlocks 5 GHz
ERROR_CODE wifi_remove(const std::string& ssid);
ERROR_CODE wifi_select(const std::string& ssid);
ERROR_CODE scan_wifi_networks(std::vector<WifiNetwork>& out);   // DEVICE_BUSY while recording/streaming

ERROR_CODE set_ble_password(const std::string& old_password,
                            const std::string& new_password);   // control password, both transports

ERROR_CODE sync_time();
ERROR_CODE get_device_time(Timestamp& out);

ERROR_CODE set_location(double latitude, double longitude,
                        double altitude = 0.0, double covariance_diag = 0.0);
ERROR_CODE get_location(Location& out);

ERROR_CODE set_configuration(int width, int height, int fps,
                             COMPRESSION_MODE codec);   // persisted; IDLE only
ERROR_CODE set_configuration(int width, int height, int fps,
                             COMPRESSION_MODE codec, IMU_DATA imu_data);
ERROR_CODE reboot();
```
The `IMU_DATA` overload also selects on-device IMU handling for the session:
`RAW` records uncalibrated samples (the default), `CALIBRATED` applies the stored
`M*S*(x-b)` per sample, and `BOTH` emits both.

## Access control and encryption

```cpp
ERROR_CODE set_usb_lock(bool locked, bool session_only = false);
ERROR_CODE set_encryption(bool enabled);
ERROR_CODE get_encryption_key(EncryptionKey& out);
ERROR_CODE create_encryption_key(EncryptionKey& out);
ERROR_CODE delete_encryption_key(const std::string& key_id, EncryptionKey& out);
ERROR_CODE factory_reset();
```

`set_usb_lock` locks or unlocks the USB control plane. Unlocked (the factory
default) USB has full privileges; locked, it gates exactly like BLE and `open()`
authenticates with `InitParameters::ble_password`. Toggling either way requires
the current password. `session_only` opens an **already locked** device for this
power session without changing the stored policy, so the device keeps reporting
`usb_locked` and loses the override when power is lost; it is refused on a device
that is not locked, and authenticating never sets it implicitly.

`set_encryption` turns at-rest encryption on or off for subsequent recordings.
Existing ones keep whatever they were written with. It returns
`INVALID_PARAMETER` when no key exists, so `enabled` never means "recording in
the clear".

`create_encryption_key` generates the device's key and returns it. This is the
only time the key is handed out in full, so the caller must keep it: it is what
decrypts every recording made from then on. It is refused with
`INVALID_PARAMETER` when a key already exists, because replacing one would make
every recording written under it permanently undecryptable. Rotation is
`delete_encryption_key` then create.

`delete_encryption_key` requires `key_id` to match the installed key (see
`DeviceInformation::encryption_key_id`), which stops a caller destroying a key it
never identified; a mismatch is `INVALID_PARAMETER`. `out` carries the destroyed
key with `present == false`, the last chance to keep it for ciphertext already
recorded. It is `IDLE` only, since a running session holds the key in memory and
would keep encrypting under it after the call reported it gone.

`factory_reset` restores defaults: password, USB unlocked, encryption off, and
WiFi, calibration, capture configuration, recordings and runtime state cleared.
It is ungated on USB only, so physical possession is the escape when the password
is lost; over BLE it needs the password like any other verb. It is refused while
a capture is active.

<Warning>
`factory_reset` **destroys the encryption key**. Every recording ever made under
it becomes permanently undecryptable, including copies already uploaded
elsewhere. Unlike `delete_encryption_key` it does not return the key first,
because it answers unauthenticated over USB and handing a key to an
unauthenticated caller is the exposure destroying it removes.
</Warning>

Read the current state from `get_device_information()`. The prose model, the CLI
equivalents, and host-side decryption with `ef-decrypt` are in
[Access Control and Encryption](/device/security).

## Calibration

```cpp
ERROR_CODE set_camera_calibration(const CalibrationParameters& calibration,
                                  int width, int height);
ERROR_CODE set_imu_calibration(const ImuCalibrationParameters& calibration);
ERROR_CODE reset_calibration(bool camera, bool imu = false);
```
All three are `IDLE` only and take effect on the next capture session.
`set_camera_calibration` persists the Double Sphere intrinsics produced by the
OpenCV calibration tool; read them back through
`get_device_information().camera_configuration.calibration`.
`set_imu_calibration` persists the IMU field calibration (bias, `M*S`, per-sensor
noise and temporal terms, the camera-to-IMU transform, and the time offset) from
the host-side solve, and round-trips through
`get_device_information().sensors_configuration`. `reset_calibration` restores the
factory default for the selected sensors; the camera factory default is all zeros
(uncalibrated).
